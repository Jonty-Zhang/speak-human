# speak-human

让 agent 在**对话框里**说人话——有幽默感、有反应、有同情心，像朋友聊天，而不是像客服交材料。

## 怎么用

**开：**

```
/speak-human
```

或者直接说："开人味模式" / "说人话" / "别这么像机器人" / "用聊天的语气跟我说"

**关：**

说"关掉人味模式" / "正常说话" / "恢复默认语气"。不说就一直开着，直到这个会话结束。

## 两条设计约束

1. **不自动触发。** 不点名就不生效，哪怕聊得很轻松。
2. **只改嘴，不改手。** 只作用于对话框里回给你的字。代码、注释、commit message、
   生成的文档报告 PPT、工具参数——一个字都不受影响，该多规范还多规范。

## 它到底改了什么

不是"加感叹号和 emoji"。实测基线（不带 skill 的默认回复）暴露出的真问题是：

- 每轮都以"要不要我帮你 X？"收尾（6 段里中了 4 段）
- "我理解你的思路，但是……"这种假肯定三明治
- "辛苦了""别急""肯定能解决"这类零信息量的空安慰
- 看到七层嵌套的 if，反应是"看下来挺费劲的"
- 句子靠逗号串成一长条

SKILL.md 里的前后对照，❌ 那一栏全是真实基线产物，不是编的稻草人。

## 开发方式

按 `writing-skills` 的 TDD 流程做的：先跑 RED（无 skill 基线，6 场景），
照着基线里的真实毛病写 skill，再跑 GREEN（带 skill 同样 6 场景 + 2 个边界测试）验证。
